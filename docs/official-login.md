# 官方豆包登录与连接

Windows 工作台支持官方扫码、官方手机号登录和连接已有会话。选择方式后会打开独立的豆包窗口；手机号、验证码、扫码内容及安全验证均留在官方界面。工作台只保存身份摘要、账号修订号及连接证明。

需要免费积分和积分任务时，在官方账号选择页选择豆包账号，不选择“飞书个人版”。成功登录只证明身份有效；活动资格和任务列表仍由当前账号的官方响应决定。没有活动入口时，任务页提示核对账号，而不生成默认任务。

## 运行依赖

- Windows 已安装官方豆包客户端。
- Python 3，以及 `tools/doubao-runtime/requirements.txt` 中的依赖。
- 桌面分发包包含固定清单内的 `doubao-runtime` 组件。组件目录中不包含 profile、账号库或捕获数据。

桌面启动器寻找可运行的 Python；网关从配套运行目录寻找连接组件。普通用户不需要配置调试端口。客户端使用数据目录内受保护的 `official-client/profile`，不附着日常豆包实例，也不修改系统代理或证书。依赖缺失或客户端不可用会明确失败，不能当作登录成功。

开发时可设置 `LOOMGATE_DOUBAO_DESKTOP_PYTHON` 和 `LOOMGATE_DOUBAO_DESKTOP_HELPER` 指向绝对路径，不设置 `LOOMGATE_DOUBAO_DESKTOP_PORT` 即使用受控模式。显式指定端口仍保留为旧开发绑定路径；该路径不是新的短信或扫码登录。

## 生命周期与恢复

`authflow.PreparedStarter` 在任何外部操作之前，将登录意图写入加密流程存储。官方窗口打开操作在私有 journal 中先记账；重启和轮询只检查已有尝试。前端支持继续当前窗口、只读核验和取消，不会自动重发短信或生成新的二维码。

`ManagedConnection` 处理官方窗口状态，并复用 `DesktopConnection` 的身份复核、账号 CAS 和幂等提交。保存前再次读取官方身份和签名模型目录；账号被切换、修改或停用时拒绝覆盖。已有会话单独标识为 `existing_session`，不能算作新登录。

`ManagedCommand` 使用有超时的私有进程管道。组件验证专用 profile、可执行文件、进程创建时间、参数和回环监听归属。缺少进程或端口被占用时不接管其他进程。重启网关会为已启用账号恢复独立官方客户端，不创建登录流程；停用账号不会被自动启用。连接失败不阻塞其他 provider。

取消进行中的操作可能留下不确定结果。反复取消不能清除该状态或重放操作，必须先核验。MFA 和未知官方状态保留具体人工待办，不伪装成验证码错误或自动绕过验证。
