# 豆包任务目录与状态

已绑定官方客户端的账号通过固定活动接口动态发现任务组，并读取该组的任务和累计奖励。上游的任务、实例、活动 ID 均来自响应；入口不接受任意 URL 或脚本。账号身份在读取和操作前后核对，非任务字段、邀请链接和个人资料不会传给网关。

管理 API 与任务界面展示上游状态、累计进度、奖励和具体所需操作。签到与领取进入现有任务引擎，提交前持久化不确定状态，操作后有界轮询并重新检查服务端结果。HTTP 200、业务接受或提交成功都不能替代奖励核验。

## 当前操作范围

- 每日签到：确认上游今日未签到后才允许提交；确认 `checked_in=true` 后仍重新读取目录。每日去重以服务端“今日是否完成”和上次签到日期组成周期，避免本机时区推断错误。
- 累计奖励：进度达到响应中的阈值或任务显示可领取后，使用当次活动组与任务代码；领取后必须读到已领取状态。
- 普通已完成任务：使用实际实例 ID；每日工作任务还需携带活动组与任务代码。实例缺失或发生变化时拒绝提交。
- 工作领域、Word、Excel、PPT 和提醒等需要真实内容或官方工作行为的任务，当前显示具体要求。网关不会伪造工作完成事件或替用户填写个人资料。
- 账号目录读取失败保留独立 issue，其余账号可继续展示。未知任务种类保留可见，不猜测自动执行方法。

当前业务状态映射依据已核验的官方枚举：Created、InProgress、Completed、Rewarded。新增任务无需更改核心调度器；具体工作执行能力仍需补充 provider 模块。

完整每日工作、一次性工作与所有奖励链尚未验收。当前活动响应中的邀请活动也不代表已经实现邀请流程。需先完成真实工作条件，再核验状态与奖励；不可通过重复文本请求或空事件刷任务。
