# 多账号任务执行与恢复

Phase16 修复 F12：Trae 全局三秒间隔曾直接返回人工状态，导致每日计划只完成第一个账号，后续账号到第二天才再次排队。现在可选 `TaskGate` 在取得执行 worker、写入未知标记和启动单项超时前排队。Trae 的共享准入通道串行准备签到，等待依据持久的 `NextClaim`，支持取消，正常最长一次间隔三秒。排队后重新检查账号、业务日、官方状态、退避和凭据；不把等待当成上游提交。

核心仍不知道 provider 任务名。一个运行按稳定目录顺序逐项处理，最多1000个任务、64个活跃运行，worker仍最多32个。准入本身也有上限（64 × 单项请求期限与准备余量），不为每个账号创建 goroutine。每个任务独立受原 `Options.Timeout` 约束，整组不会因为前几个账号消耗了共同超时而丢失后续账号。一个账号失败/未知不阻断其余账号，整体保留失败或待核验结果。

## 状态 v3

`work` 保存已发现的原任务实例、下一个游标、累计结果、已确认项和取消意图。任务列表在第一项操作前落盘，写操作仍先保存 `uncertain`。确认结果与本轮确认标记在同一次原子写入中保存，避免崩溃后重复执行非每日任务。

进程关闭或崩溃后，注册对应 adapter 会恢复尚未开始的工作，同一个 run ID 和同一次每日计划继续；不会再创建一次计划派发。先前未知的写入只检查权威状态，绝不因恢复游标而重发。若只剩未知项，运行恢复为终态待复核，保留原有“用户明确复核”行为。取消已持久化的运行不自动恢复。活动换期仍使用原实例，provider会拒绝跨日写入。

读取v1/v2时保留旧历史与F11证据语义；v1完成缓存仍不升级信任，v2有效动作回执完整保留。v3增加可恢复工作，旧程序会因版本不支持而拒绝写入，不能将旧 writer 指向新库。状态最多32MB，写入与读取都检查上限。

Phase17状态格式升级v4，额外保存动作发出前的attempt绑定，用于恢复同一次保活响应；它不是接受回执。所有v3工作游标、取消、unknown与已有回执保持，缺历史attempt不猜测。`ActionReference`只在引擎实际发起或恢复该阶段时可用，目录不能伪造，公开Task JSON不包含attempt。旧writer拒绝v4。

验证包含原 F12 未改断言（三次）、整组耗时超过200毫秒单项期限但仍保持三秒间隔、未知后重启继续第二个账号、取消、间隔中停用/换日，以及原真实子进程被杀后的未知提交不重放测试。所有账号与上游合成；真实每日任务 `NOT RUN`。

## 本地退避恢复入口

可选 `DeferredRequestAdapter` 提供已持久化的具体恢复候选，不在回调中联网或执行动作。每秒普通计划调度之后，引擎传入启用且无冲突运行的计划快照，回调完成后再次校验实时计划和单账号范围；恢复不能扩成通配符或任务序列。回调失败不终止其他供应商和普通调度，已预留的部分结果仍可经原执行链提交。

回调使用深复制的计划，受独立串行锁和关闭等待保护。活动任务不会重复排队，未确认动作按账号隔离，不因另一个账号恢复而重写原证据。内部 `ExpectedPeriodKey` 跟随恢复运行持久化，发现与恢复游标都必须匹配原周期；它不接受管理API的客户端输入。普通计划、手工核验和既有状态版本保持兼容。

## 任务日志统计

新运行保存按账号、任务和周期去重的最终结果投影。日志头尾按账号汇总已核验、失败、需人工、待核验和跳过；一个账号有多项结果时取仍需关注的状态，进行中的后续步骤不会因前一项成功而被算作整账号完成。官方明确拒绝及业务码另作原因细分，不重复加入账号总数。统计中的“已核验”只指本次操作，不承诺上游完整任务或奖励到账。

步骤调用成功、输出文案和历史整轮状态不用于反推逐账号成功；旧日志缺少最终结果时明确显示记录不足。全部账号范围只统计本轮已记录账号，不冒充账号池总数。超过显示上限时保留结束状态及最终统计。结果投影最多1000项、记录失败不改变业务返回、账本、未知保护或重试，统计自身从不作为执行许可。
