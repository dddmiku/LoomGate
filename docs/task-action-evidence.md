# 任务动作证据与兼容

Phase15 修复 F11：Phase14 引擎把 `Claim/Execute` 的 `err == nil` 当成接受回执，但适配器动作前复查可能返回 `manual,nil` 并完全没有请求。旅行记录随后消失会因此被错误判为奖励成功。原独立测试保持语义，三次红测再三次绿测；生产调用链回归已入库。

`Observation` 的业务阶段与动作证据分离。动作证据绑定 provider、账号、任务key、原周期、阶段和本次随机attempt；不进入公开响应或日志。调度器只信任本次调用返回且绑定相符的证据。

| 动作结果 | 适配器条件 | 引擎处理 |
|---|---|---|
| `NotSubmitted` | 尚未进入任何写入传输；前置检查取消、停用、条件变化 | 只撤销本次预写unknown；保留更早动作；按人工/失败/跳过记录，不伪造成功 |
| `Rejected` | 有明确无效果业务拒绝及安全数字码；不是泛化HTTP错误 | 审计为rejected并保留业务码；只释放本次临时标记，之后仍须重新检查状态 |
| `Accepted` | 实际写入的业务接受证据已验证 | 持久保存本次绑定回执，仍须独立Verify确认最终状态 |
| `UnknownAction`、缺失证据或绑定不符 | 网络异常、解析失败、结果未知，或旧适配器没有明确证据 | 不制造回执、不自动重发；只能通过独立权威状态核验 |

`nil error`、HTTP200、pending/manual/blocked/done阶段、空目录和记录消失都不能生成回执。旅行领奖还必须有明确业务码0与有效奖励字段；只返回HTTP200但漏业务码属于未知。其他已接入的5模块、WorkBuddy签到/成长领取和豆包动作均审计前置无提交路径。只读资源模块没有写动作。

状态格式升为v2。旧v1运行历史与unknown完整保留；旧 `accepted_stage` 不转成新回执，原完成缓存移到 `legacy_completed` 后重新读取权威状态。不能根据历史成功step补造动作证据。新回执对任务/账号/周期/动作/attempt不匹配时拒绝加载。旧程序拒绝v2，不能用旧writer降级写新库。

取消后收到的真实已接受响应可保存回执，但本次运行仍不宣称完成；取消前确认未提交则不永久锁unknown。前一个已接受动作之后的无提交分支也不能清掉前者。未知实例换期、目录消失和陈旧排队请求仍沿用Phase14保护。

本修复只在合成上游及独立本地测试库验证。历史真实豆包签到、领奖保护没有更改；没有为了修复清保护或重发真实任务。
