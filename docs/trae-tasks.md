# Trae 独立任务模块

Phase15 将 Trae 余额与到期桶从签到中拆成独立任务，并将签到退避、业务日缓存和全局提交间隔持久化。新控制台任务目录、逐项执行和计划编辑使用现有真实管理接口。

`traeBalanceModule` 只调用官方权益接口，验证业务码、总量/已用和包列表。Phase16修复F13，严格检查原始 `entitlement_base_info.product_extra.package_extra.quota.credits_limit`、usage 与支持的 end_time/expire_time，不能用宽松 parser 的默认零代替字段证据。合法空 usage 表示未用，缺失或畸形 usage 失败。独立 `TaskExpiry` 校验数值范围、排除已到期包，用有界加法将到期桶限制在总余额内，避免溢出。异常完整快照不会覆盖任何旧余额/到期桶。

`traeCheckinModule` 先检查官方 enable/checked_in，提交一次后再次读取账号状态。严格 `TaskClient` 使用既有官方URL/头字段和稳定设备代数，保留取消与30秒超时，禁止重定向写请求。缺业务码、缺布尔字段或网络失败不能成为成功回执。

| 官方结果 | 行为 |
|---|---|
| code0接受 | 保存本次动作回执，再由账号checked_in确认；不凭HTTP200完成 |
| 9074 | 明确记录本次被拒；持久退避60/120/240/480秒。同日退避到期后，可在当前启用计划的账号范围内自动核验并补试，每账号每天最多三次；单次执行不循环重发 |
| 9095设备已签 | 不当作账号成功；保留当日暂停并提示官方核验，不旋转设备号强行重试 |
| 鉴权/其它业务错误、传输/模式错误 | 可理解的失败或unknown；不猜测成功、不自动刷新凭据或重放未知写入 |

退避、确认签到日和全局3秒提交间隔保存在 `data/task-provider-state` 的accountvault中，AES-GCM和平台保护沿用现有安全库。存储异常明确失败，不以空状态启动；注册表最多1000账号。生产组合负责唯一持有与关闭。账号标识使用摘要索引，回执/上游文案不落此库。

签到业务日沿用原Trae约定CST，计划执行时间可在面板自由指定时区、小时、分钟和账号范围。业务日去重与计划时间是不同规则；重启不丢退避，不重复派发旧时点。余额可配置独立多次计划。

模块回归使用真实HTTP和真实浏览器，但账号、上游、时钟均为隔离合成fixture：9074、重启、独立余额/到期桶、后续接受与复核、已签不重放、缺字段不清零、计划保存及窄屏。这些测试不作为真实账号签到成功或奖励到账证明；现网核验与受控操作另存私有证据。

Phase16修复F12：全局间隔不再把后续账号退成人工终态，改成可取消有界排队与持久运行游标；超过单项超时的账号组仍逐项处理，重启续作不重发未知。详见[多账号恢复](task-work-recovery.md)。新增[独立保活模块](account-keepalive.md)负责官方续期、凭据保存和停用保护。旧设备轮换策略不自动迁入；Phase16当时未执行真实账号签到、奖励或续期，也未变更线上排程和生产数据。

## 9074 退避到期后的恢复

`Accounts.TakeDeferredRequests` 只读取本地持久状态，每轮至多预留一个明确被9074拒绝的账号。引擎在锁外调用它，随后重新检查计划启用、具体任务和单账号范围，再经原 `checkin` 任务的发现、账号锁、动作账本与官方复核执行，日志标为“退避后自动核验”。恢复不推进计划的 `NextRun`、`LastDispatched`，也不改变用户暂停的计划。

自动补试次数和至少60秒的预留间隔持久化，进程重启不会清零。预约绑定原业务日，重新发现或排队跨日不会变成次日的新签到；前一日的9074冷却也不会吞掉次日正常计划的官方状态核验。旧状态只在拒绝时刻和退避截止均可证明属于当日时接续。存储不存在或损坏时不以空白重试预算继续。

真正发送前先关闭自动恢复资格；仅新的明确9074可重新排队。认证错误、9095、活动未开放、已完成、账号停用/移除或未知结果均不授权重放。已有 `unknown/pending/attempt` 继续保留，另一个账号仍可独立恢复。崩溃或计划变更最多可能消耗一次已预留机会，不会因此增加次数或清除未知保护。
