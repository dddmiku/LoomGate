# Trae 独立任务模块

Phase15 将 Trae 余额与到期桶从签到中拆成独立任务，并将签到退避、业务日缓存和全局提交间隔持久化。新控制台任务目录、逐项执行和计划编辑使用现有真实管理接口。

`traeBalanceModule` 只调用官方权益接口，验证业务码、总量/已用和包列表。Phase16修复F13，严格检查原始 `entitlement_base_info.product_extra.package_extra.quota.credits_limit`、usage 与支持的 end_time/expire_time，不能用宽松 parser 的默认零代替字段证据。合法空 usage 表示未用，缺失或畸形 usage 失败。独立 `TaskExpiry` 校验数值范围、排除已到期包，用有界加法将到期桶限制在总余额内，避免溢出。异常完整快照不会覆盖任何旧余额/到期桶。

`traeCheckinModule` 先检查官方 enable/checked_in，提交一次后再次读取账号状态。严格 `TaskClient` 使用既有官方URL/头字段和稳定设备代数，保留取消与30秒超时，禁止重定向写请求。缺业务码、缺布尔字段或网络失败不能成为成功回执。

| 官方结果 | 行为 |
|---|---|
| code0接受 | 保存本次动作回执，再由账号checked_in确认；不凭HTTP200完成 |
| 9074 | 明确记录本次被拒；持久退避60/120/240/480秒。后续计划/人工运行到期后先查状态，不在单次执行中循环重发 |
| 9095设备已签 | 不当作账号成功；保留当日暂停并提示官方核验，不旋转设备号强行重试 |
| 鉴权/其它业务错误、传输/模式错误 | 可理解的失败或unknown；不猜测成功、不自动刷新凭据或重放未知写入 |

退避、确认签到日和全局3秒提交间隔保存在 `data/task-provider-state` 的accountvault中，AES-GCM和平台保护沿用现有安全库。存储异常明确失败，不以空状态启动；注册表最多1000账号。生产组合负责唯一持有与关闭。账号标识使用摘要索引，回执/上游文案不落此库。

签到业务日沿用原Trae约定CST，计划执行时间可在面板自由指定时区、小时、分钟和账号范围。业务日去重与计划时间是不同规则；重启不丢退避，不重复派发旧时点。余额可配置独立多次计划。

验证使用真实HTTP和真实浏览器，但账号、上游、时钟均为隔离合成fixture：9074、重启、独立余额/到期桶、后续接受与复核、已签不重放、缺字段不清零、计划保存及窄屏。真实Trae账号请求与奖励到账为 `NOT RUN`。

Phase16修复F12：全局间隔不再把后续账号退成人工终态，改成可取消有界排队与持久运行游标；超过单项超时的账号组仍逐项处理，重启续作不重发未知。详见[多账号恢复](task-work-recovery.md)。新增[独立保活模块](account-keepalive.md)负责官方续期、凭据保存和停用保护。旧设备轮换策略不自动迁入，真实账号签到/奖励/续期仍为NOT RUN；不变更线上排程或生产数据。
